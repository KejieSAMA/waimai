# 盟信外卖平台

Vue 3、Express、Prisma 和 SQLite 构成的 pnpm workspace，包含用户、商家和管理三种角色的 PC 与手机应用。

## 本地启动

使用 Node 22 和 pnpm 10。

```powershell
pnpm install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# 先配置 .env 中的随机签名密钥
pnpm db:setup
pnpm --filter @waimai/backend account:init
pnpm dev
```

服务默认监听 `0.0.0.0`。PC 端口为 `13599`，手机内部开发端口为 `5174`，API 默认端口为 `3000`。当前电脑的 `3000` 已占用，本地 `.env` 使用 `3001`，开发代理已同步。浏览器统一访问 [用户首页](http://localhost:13599)。局域网设备使用开发电脑的 IP 和 `13599` 端口访问。

| 入口         | PC                       | 手机               |
| ------------ | ------------------------ | ------------------ |
| 用户         | `/`                      | `/mobile/`         |
| 商家         | `/merchant`              | `/mobile/merchant` |
| 管理         | `/admin`                 | `/mobile/admin`    |
| 开发组件画廊 | `/__ui`（antd 主题预览） | `/mobile/__ui`     |

PC 的 Vite 代理 API、上传文件和整个 `/mobile` 路径。手机 HMR websocket 也经过这个入口。端口被占用时启动会报错，可在 `.env` 修改对应端口。

无 `/mobile` 前缀的入口按设备识别：电脑保留 PC，手机进入对应手机版；明确访问 `/mobile`、`/mobile/` 或其子路径时始终保留手机版，包括电脑直接输入、书签和外部链接。设备识别优先使用 Client Hints 的手机标识，不支持时回退到 UA 与 iPad 平台、触控信息；Windows 触屏电脑保持 PC，窗口宽度不参与判断。

普通入口进入后，本次自动跳转和站内浏览仍随设备标识实时切换。自动跳转会携带临时 `__xz_auto_entry=1` 参数，到达后在 Vue 挂载前立即移除，仅在当前文档内存中区分来源；不保存到 localStorage、sessionStorage、Cookie 或历史状态。刷新已清理的 `/mobile` 地址后视为明确访问，固定手机版；重新访问无前缀地址恢复自动识别。设备版本偏好及切换按钮已删除，启动只尝试清理旧 `xz-device` 键，不影响主题、账号或购物车。

自动模式在窗口变化、页面恢复、重新获得焦点和恢复可见时以 150ms 合并检测，尺寸变化本身不换端；明确手机版入口不监听这些事件。跳转使用 replace，保留当前页面、查询参数、登录回跳及锚点，卸载和热更新时清理监听及定时器。开发者工具若刷新后才更新设备标识，刷新后按上述入口规则判断；不探测工具栏按钮本身。

## 正式账号

三端保留独立账号名，支持账号或手机号配合密码登录。公开注册手机号必填且唯一，昵称选填，留空时使用手机号；管理员创建无手机号账号仍受支持。不提供固定验证码或默认密码。首次运行前必须将 `.env` 中的 `JWT_SECRET` 改为随机密钥（至少 32 字符），模板占位值在开发和生产环境都会被拒绝。

迁移及基础类目初始化完成后，在本机交互终端创建首个管理员：

```powershell
pnpm --filter @waimai/backend account:init
```

账号和密码由操作者输入，密码不回显；没有默认管理员。已有启用管理员时不能再次初始化。忘记管理员密码可由有服务器操作权限的人运行 `pnpm --filter @waimai/backend account:recover`，恢复后首次登录必须改密。

普通用户在用户登录页注册，只获得用户身份。管理员在账号管理中创建账号、授权用户／商家／管理员身份、启停用或重置密码；商家身份获得授权后仍需提交入驻审核。角色切换位于账号设置，只显示已授权角色；浏览器只有一个当前身份，访问后台不会恢复另一账号的旧会话。临时密码首次登录必须修改，忘记密码联系管理员。

本次升级禁用旧账号、移除旧密码并撤销会话，冻结关联店铺，保留店铺、商品、订单及地址数据。管理员核对资料、重置密码并启用账号后，仍须单独解冻店铺。迁移备份与恢复步骤见 [账号迁移说明](docs/ACCOUNTS_MIGRATION.md)。初始化不再创建演示账号、店铺或订单。

## 主要操作

- 用户选择菜品，在结算页选择配送或自提，提交后进入订单详情进行模拟支付。配送中或待自提订单可以确认完成。订单详情提供取消、退款、申诉和评价入口。
- 游客购物车保存在本地，用户登录后按账号及店铺保存在服务器；登录自动合并游客商品，跨设备进入或恢复页面时同步，退出不将账号商品留给游客。加购不锁库存，下单重新核验。旧 `xz-cart` 不导入，升级与冲突处理见 [购物车说明](docs/SERVER_CART.md)。
- 商家工作台和订单页面可开启提醒。开启时浏览器取得音频播放授权，并建立 SSE 连接。接单后出餐，退款申请可同意或拒绝。
- 商家商品管理提供上下架、库存筛选和编辑。PC 提供批量上下架与改库存。管理员强制下架的商品须修改后重新审核。
- 管理端提供账号管理，处理入驻审核、冻结和解冻，进行商品巡检、订单监管、退款裁定和平台类目管理。关键动作写入审计记录。
- 商家可筛选并回复本店评价、修改回复，配置版本化多档满减；满减不叠加，配送与自提都取最大优惠。PC 三种身份均可编辑本人昵称及联系手机。
- 创建订单必须携带服务端报价指纹，金额变化需要再次确认；支付期限为 15 分钟，到期由接口和后台任务共同防护。支付／退款仍是模拟流程，不连接真实资金。评分来自真实评价，新店显示暂无评分；月售按近 30 个上海自然日完成订单统计。迁移和人工验收见 [购买修复说明](docs/PURCHASE_REPAIRS.md)。
- 主题支持跟随系统及手动切换。设备版本不保存偏好；普通入口自动识别，明确手机版 URL 优先。一个账号可拥有多个授权角色，同一浏览器仅保留当前账号及当前角色。

## 目录

| 目录              | 内容                                                   |
| ----------------- | ------------------------------------------------------ |
| `design-system`   | 原始只读设计规范                                       |
| `design-demos`    | 用户端 PC 设计方案 demo（ant-design-vue）              |
| `packages/tokens` | 原样复制的 token、组件 CSS、本地 Barlow 字体与主题逻辑 |
| `packages/ui`     | 两端共享的 Vue SFC                                     |
| `packages/shared` | 类型、状态映射、格式化与可注入传输层的 API 客户端      |
| `frontend`        | PC 三角色应用，方案 A 主题 + ant-design-vue 4          |
| `mobile`          | `/mobile/` 手机三角色应用                              |
| `backend`         | 鉴权、业务模块、领域状态机、数据库迁移、种子与测试     |
| `docs`            | 详细规格、计划、决定、检查记录与部署说明               |

API 使用 `/api/v1`，成功响应为 `{ code: 0, message: 'ok', data }`。金额以整数分保存，订单保留价格和地址快照。数据库文件和上传文件已加入 Git 忽略规则。

距离排序需要接入定位坐标，当前首页提供综合、销量和起送价排序。实现决定见 [开发决定](docs/DECISIONS.md)。

页面设计对照与本轮数据口径见 [设计稿对齐记录](docs/DESIGN_ALIGNMENT.md)。开发画廊增加 20 个页面的深浅色原稿与业务页面入口，UI 由人工验收。
