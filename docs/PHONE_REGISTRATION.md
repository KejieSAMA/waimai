# 注册手机号与密码登录（2026-11-14）

## 当前规则

保留独立账号名与密码。公开注册必填大陆 11 位手机号（1[3-9] 开头），修剪首尾空格；昵称选填，修剪后留空或省略时由服务端使用手机号，填写后最长 30 字。密码仍为至少 8 个字符、不超过 72 UTF-8 字节；仅授予 USER，无短信或固定验证码。

登录 username 字段同时接受账号和手机号。先匹配完整账号名，再以手机号查找；密码、角色授权、账号启停用、首次改密和统一会话规则保持。账号及手机号共用账号级失败次数，成功后清除两个入口的失败计数。新设置的手机号不可与其他账号／手机号形式的账号名冲突，旧数字账号原样保留。

User.phone 添加可空唯一索引，非空手机号只能属于一个账号。注册、管理员创建／编辑账号、管理员代建商家账号和本人资料改号在事务内检查，唯一索引处理并发或直接写入绕过。管理员创建账号仍可不填手机；资料页仍可清空手机并使用账号登录，无手机账号不会被删除。新手机号保存后成为该账号的手机号登录入口。

PC、手机注册表单均为账号、密码、必填手机号、选填昵称；失焦及提交校验复用共享逻辑，登录标注账号或手机号。未填昵称只在服务端注册时回退，不随后续改号自动重写昵称。注册冲突不自动绑定、覆盖或登录原账号。

## 迁移

迁移 `20261114010000_unique_account_phone` 仅增加 User_phone_key，不回填或清空任何资料。部署前必须备份 SQLite，查询非空 phone 的重复分组；若重复，停止部署并人工核对，不自动修改手机号或删除账号。先在备份副本验证索引、所有业务行和外键，再 db:generate／db:migrate，同步更新前后端。

本机备份：`.cache/phone-migration-20261114-100043/before.db`；副本 verification.db 完成验证后部署，原有 5 个账号及所有业务表逐行一致，外键和完整性检查通过。API 已恢复。备份不入 Git；没有创建业务测试账号、没有生产编译或自动 UI 验收。
