# 手机用户端购买链路 UI（2026-11-14）

本轮只调整手机用户端：首页、店铺、本店购物车 sheet、确认订单、订单列表和详情。PC 的订单展示与倒计时上提为共享控制逻辑，PC 使用原路径的显式转导出，布局及业务行为不变。商家、管理端默认组件、design-system、packages/ui 和 packages/tokens 保持不变。无业务接口或数据库迁移，未编译、未执行自动 UI 验收。

## 浏览选购

首页商家卡突出名称、营业状态、评分销量，费用为次级，最多两条优惠；店铺使用紧凑摘要，全部优惠及公告放商家页签，菜品名称最多两行。休息和不可用均有明确说明，不清空既有购物车。

首页保存已成功应用的搜索、分类、排序、已加载列表及正文位置；店铺按 ID 保存搜索词、页签、分类、菜品／分类／资料视口位置及公开评价页。仅文档内存，按身份 revision 隔离，不新增本地存储；刷新重新读取。新页面进入从正文顶部开始，恢复位置也通过实际正文视口，不滚动窗口。成功筛选才回顶，失败保留内容及位置；追加请求失败重试原页、去重、防重入，卸载隔离迟到响应。

购物车仍为本店 sheet：店名、商品、服务端费用分开，固定底部清空本店（确认）与去结算；底栏保留旧金额，辅助状态固定一行，不将报价失败显示为登录提示。

## 确认订单

配送／自提、地址或真实门店摘要在第一卡，不再重复配送信息大标题。商品卡保留切店与继续选购，默认三行商品，可展开全部／收起清单；总件数不受折叠影响，数量或报价刷新不收起，商品错误自动展开且不允许隐藏错误。正文整体滚动，不增加商品内部滚动。

备注改成摘要入口，sheet 使用局部草稿，最多 300 字，保存后才写本店购物车；取消不写回，放弃修改需确认。配送地址保存、提交期间锁定切店；成功创建后允许跳转订单详情，不因离开保护再次停留结算页。原报价指纹、库存校验、购物车版本及一次一店提交逻辑不变。

## 订单管理

用户专用订单卡单列：店名与状态、占位图与商品摘要、时间／配送方式／件数、金额及最多两个按钮。无图片快照不请求现商品图。待支付显示应付、取消显示订单金额，其余实付；每卡最多一个主按钮，保留原四个 Tab 和加载更多。

详情分状态、商品费用、配送、订单资料四区；正常订单五节点进度，取消及退款仅显示真实说明，不编造履约时间。商品默认三行，费用读服务端快照、零配送免配送费、零优惠和空备注不占行。编号完整可见且可复制，HTTP 不支持剪贴板时提供只读可选中文本。

固定底部操作：待支付模拟支付＋更多（取消）；待接单更多（取消／退款）；备餐中更多（退款）；配送／自提确认完成＋更多（退款）；完成未评价为评价；退款拒绝未介入为申请介入。无操作则无空栏，详情不显示业务 Tab，安全区由 MobilePage 负责。

取消、完成先二次确认。退款／评价 sheet 内部滚正文，标题及操作固定，失败保留输入，忙碌时锁定关闭与重复提交，脏草稿关闭／导航确认。原 #review 深链接直接打开可评价 sheet，已评价显示已提交。不同订单、身份变动及卸载隔离旧响应。倒计时仅可见待支付时更新，按服务端期限到期禁用、刷新；原 15 秒状态轮询保留。
