# 开发决定

- 2026-11-11，最新用户要求优先于阶段编译和自动视觉验收条款，本次执行 lint、无产物类型检查及测试，编译和界面验收由用户安排。
- 2026-11-11，所有服务监听 0.0.0.0，PC 端口使用 13599，手机内部端口保留 5174，统一入口保持 PC 代理方式。
- 2026-11-11，SQLite 使用字符串状态并由 zod 与领域状态机约束，方便切换数据库 provider，切换 MySQL 时需更改 provider 并重新生成迁移。
- 2026-11-11，新增订单完成接口和退款申诉接口，补齐 SPEC 中配送完成、自提完成和纠纷介入所需入口。
- 2026-11-11，未接真实短信服务时固定验证码仅在开发环境可用，生产环境需实现 SmsProvider 后启用短信登录。

- 2026-11-11，订单完成与退款申诉分别采用用户端 complete、dispute 接口，以支持现有订单流程的后续动作。
- 2026-11-11，商家拒绝退款后保留退款中状态并标记拒绝，用户申请介入后由管理员裁定，同意则回补库存，拒绝则恢复退款前状态。
- 2026-11-11，证照上传携带 certificate 用途并保存所有者元数据，文件读取要求所有者或管理员的 Bearer 身份，以保护材料访问。
- 2026-11-11，现有数据模型未提供坐标，首页提供综合、销量和起送价排序，距离排序待接入定位数据后实现。
- 2026-11-11，手机浏览器使用真实设备安全区，页面骨架省去预览用模拟时间状态栏。
- 2026-11-11，SQLite 初始化先创建空数据库文件，再部署迁移，解决当前 Windows Prisma 对缺失文件的初始化错误。
- 2026-11-11，事务使用 Serializable 隔离级别，数据库并发冲突返回 409，客户端可刷新后重试。

- 2026-11-11，当前电脑 3000 端口已有服务，本地未提交的 .env 将 API 设为 3001，开发代理随环境变量读取，对外入口保持 13599。

- 2026-11-11，按本次首页调整要求移除 PC 页脚切换区域和顶栏搜索，首页分页固定在视口底部居中；主题切换沿用现有记忆逻辑，浅色显示太阳、深色显示月亮，图标遵循现有 24px 网格与线宽。
- 2026-11-11，商家卡片取消促销与公告行，将休息中文字移至店名旁，配合居中灰色 Logo 保留状态文字表达；应用可见品牌统一为盟信。
- 2026-11-11，PC 购物车在异步报价期间保留上次金额并禁用结算，响应完成后替换金额；数量调整保留商品行顺序，清空、换店和报价失败时清除旧金额。
- 2026-11-11，PC 店铺页左上角复用 back SVG 图标返回商家列表，演示店铺老张家牛肉面的种子商品增加到 24 款，便于人工查看滚动效果。
- 2026-11-11，PC 通过 Vue 注入统一启用原生滚动与覆盖式滑块，滑块宽 6px，采用现有中性色 token 混合透明度，不占布局空间；手机端保持原有滚动方式。
- 2026-11-11，PC 店铺页约束到视口高度，商品与分类分别滚动；购物车行高保持 49px，可视上限为 5.5 行，矮窗口优先缩小商品区域以保持金额与结算入口可见。
- 2026-11-11，两套 Vite 开发服务显式监听共享包入口，入口变更时清除模块图缓存并整页刷新，避免新增导出后浏览器仍读取旧版本模块造成白屏。
- 2026-11-11，按用户最新样式要求，PC Select 使用设计 token 绘制选项浮层，统一选中态、圆角、阴影与滚动条；通过 PC 应用注入启用，并保留原有 Select 数据接口。
- 2026-11-11，店铺返回图标按钮固定为 40×40，位于店铺信息区左上角，使用现有圆角和表面色 token 绘制正圆。
- 2026-11-11，按最新设备状态自动路由要求，将原来仅 PC 加载时执行的 UA 检测改为两端统一检测：手机 UA（含桌面 UA 的触屏 iPad）或小于 768px 的视口使用手机版，否则使用 PC；启动前、窗口变化和页面恢复时判断，手动偏好继续优先，以支持设备模拟与窗口切换并避免双端来回跳转。
- 2026-11-11，设备路径转换仅添加或移除完整 /mobile 前缀，保留角色、详情 ID、查询参数、登录回跳与锚点；共用纯逻辑放入 shared，浏览器 API 与监听清理留在应用内，手动切换不再将“我的”页面重定向到首页。
- 2026-11-11，按确认后的修正方案废除上述宽度分流：优先使用 Client Hints 的 mobile 布尔值（false 同样有效），缺失时回退 UA 与 MacIntel 多点触控 iPad 识别，未知设备和 Windows 触屏电脑使用 PC；参考 [is-mobile](https://github.com/juliangruber/is-mobile/blob/main/index.js) 与 [Chrome Client Hints](https://developer.chrome.com/docs/privacy-security/user-agent-client-hints)，将设备身份与布局宽度分开，避免开发者工具或窄窗口触发整站跳转。
- 2026-11-11，xz-device 升级为 version 2、mode、detectedMode 的 JSON 记录，仅同一设备状态下应用手动偏好；检测状态改变、旧字符串或无效记录时自动清除，仅操作该键，不要求用户清理控制台存储。
- 2026-11-11，初次检测在挂载前立即执行，后续 resize、pageshow、focus、恢复可见和设备偏好存储事件以 150ms 合并重读设备信息；跳转、卸载与热更新时清理所有监听及定时器，浏览器设备标识需刷新才变化时沿用浏览器行为，不探测开发者工具内部状态。
- 2026-11-11，本轮按 UserOrders 与 DeskUserOrders 参考组合校正订单列表：手机不额外添加“我的订单”标题、主题文字按钮和外层内边距，PC 使用账号侧栏、PageHeader 与双列订单；保留用户已要求的盟信品牌、顶栏去搜索、主题图标、独立滚动等改动，design-system 继续只读。
- 2026-11-11，用户订单按全部、进行中、待评价、退款四组查询，新增 tab=all|ongoing|unreviewed|refund；分组、归属、总数和分页统一在后端处理，返回评价 ID 以避免已评价订单重复显示评价入口，保留原 status 查询并与分组取交集。
- 2026-11-11，卡片按真实状态给出评价、再来一单、查看进度和查看订单操作，日期使用上海时区的今天／昨天／月日格式；再来一单先获取当前商品并由后端验证报价，有购物车时确认替换，验证失败保留原购物车。
- 2026-11-11，当前缺少骑手、预计送达、独立评价列表和优惠券接口，不伪造相关数据或电话；配送卡片保留查看订单，账号侧栏的我的评价与优惠券标为暂未开放，页头显示实际订单总数，不虚构近三个月范围；模拟系统状态栏与手机外框仍不进入产品页面。
- 2026-11-11，全面对齐按原始页面组合逐项推进，已要求的视觉改动继续覆盖原稿；手机以页面操作槽区分 Tab、购物车和固定提交区域，使用原生 form 关联保留表单校验，详细对照与验收项见 DESIGN_ALIGNMENT.md。
- 2026-11-11，商品草稿使用已有 OFF 状态，最多 5 张图片，划线价必须高于售价；商品审核分组包含驳回，商家配送分组包含待自提，所有分组和计数在后端处理。
- 2026-11-11，工作台、总览与待办从现有订单、商品、店铺和评价模型汇总，访问与转化字段暂为 null，不伪造增幅或新增埋点；统计按上海日期创建的订单计算，新入驻按店铺创建日期计算，今日排行使用真实已支付有效订单。
- 2026-11-11，店铺评价公开接口仅返回评分、正文、回复及评价 ID，不暴露用户身份；管理列表可返回负责人及状态分组数量，公开列表继续隐藏这些管理信息。
