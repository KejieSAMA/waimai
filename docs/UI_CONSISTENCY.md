# 三端 UI 与交互一致性（2026-11-13）

## 实现范围

- 商品基础信息的标签排布、640／960px 的列数规则和预览位置保持当前版本，未改布局 CSS。PC 保留方案 A；手机继续使用共享组件。
- 表单共享字段反馈：失焦提示、提交全量校验、嵌套字段映射、首错定位；读取失败锁定编辑并允许重试。商品、店铺、本人资料、满减、创建店铺、账号和类目编辑均保留失败草稿并互斥保存。登录、改密及地址表单补齐就近反馈。
- 有修改、非只读且读取完成后可点击提交触发校验；无效输入不发请求。草稿只驻留内存，不增加自动保存、浏览器草稿或密码存储。登录遇到网络／限流／服务错误保留内存密码，凭据错误和成功后清空。
- 商品和店铺及现有资料／满减／创建页面共用身份感知的离开保护：覆盖路由离开、同组件路由更新和刷新；保存／上传期间阻止离开，身份失效始终放行。账号、类目、回复编辑也覆盖导航离开。
- 手机入驻／店铺设置改为基础、营业配送、资质三张同页卡片，固定保存区；资质仍选填，已通过资料只读，冻结只读。取消修改先确认，不新增资质变更或营业规则。

## 组件规则

- PC modal／drawer 的正文接入 ScrollArea，标题与操作区位于正文外；沿用覆盖式 6px 滑块，内边距容纳焦点环，不增加 gutter。手机编辑采用 sheet，短确认保持现有形式。
- `Dialog` 增加 `confirmDiscard`／`dirty` 与可调用的 `close()`。取消按钮与遮罩／Escape 共用关闭决策；提交锁定优先于放弃确认。显式 dirty 使用实际草稿比较；未提供时，以输入事件保守提示。
- PC 与共享 Dialog 复用顶层栈，只有最上层处理 Escape／焦点约束，关闭恢复触发位置。PC 下拉框和日期浮层保留自身键盘处理。读取可取消，详情版本号隔离关闭、重开后的旧响应。
- 输入框和选择框使用稳定 ID、标签及错误说明关联，并暴露 focus；保留当前标签布局。商品上级面包屑为 RouterLink，支持键盘及新标签页。
- DataTable 仅在 `rowInteractive=true` 时允许整行点击、Enter／Space 和手形光标；行内按钮、链接、输入框等独立处理。

## 列表规则

- 手机账号、商品巡检、订单监管、退款纠纷和商家评价保留上一页／下一页。请求成功才提交页码，通过 MobilePage 提供的正文视口接口回到列表起点；失败保留原页、原数据、原位置，并重试原目标页。背景刷新及其重试保持滚动位置。
- 已有加载更多继续追加，失败保留行和页码；用户订单与商品、商家、商家订单修正失败重试的追加语义，避免跳过失败页或覆盖前页。新筛选和卸载隔离旧响应，不自动重试写请求。
- 读取区分初次加载、背景更新、失败、成功空数据。巡检、监管、账号、评价及类目提供局部错误和重试，不把读取失败显示为空数据。
- PC 工作台按后台内容区宽度适配：小于 560px 单列，560–959px 两列统计，960px 起恢复原列数；小于 960px 图表和待办上下排列。筛选／操作可换行，不改变设备分流。
- 巡检以真实店名提供上下文，不展示长店铺 ID；底层 ID 继续用于操作。长文本保留 title／原有详情查看及换行，未恢复删去的大标题和提示文案。

## 接口兼容

保留原错误码、`details.reason`、`fieldErrors`、`formErrors`，校验错误附加可选的 `details.issues: { path: (string | number)[], message: string }[]`。例如嵌套账号字段使用 `['account', 'username']`。响应只含路径和消息，不回显输入值；普通 API 和两端认证传输均保留这些信息。无新业务接口、模型、数据库迁移。
