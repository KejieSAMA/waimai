# 登录核验与权限恢复

## 用户可见行为

- PC 与手机共用会话及回跳判定。首次核验时只有加载提示；网络／服务失败显示核验失败与重试，不展示旧账号，也不当作游客。
- 无 Cookie、无效／过期／撤销会话进入目标角色登录页，携带业务深链接。直接访问裸 `/access` 的游客进入用户登录，不再将 `/access` 自身作为登录回跳。
- 已登录但当前身份不符时显示当前账号、当前身份、所需身份和目标页面，只能明确点击“切换身份”后继续。账号未获目标授权时显示“暂无访问权限”，可返回当前身份首页或确认退出后更换账号；没有虚假的申请权限入口。
- 已登录直接进入没有有效目标的 `/access` 时返回当前身份首页；已满足目标授权时原样继续。强制改密优先，深链接经改密和重新登录后保留。
- PC 权限页使用方案 A 下的自定义 Result 图标、简化品牌顶栏和主题按钮；手机使用现有 NavBar、图标、纵向按钮及退出确认 sheet，无业务 Tab。移除权限页中的资料／改密卡片。
- PC 用户站点顶栏读取实际登录账号，管理员／商家浏览公开页面时不再假显示“登录”；账号入口进入实际当前身份“我的”，不自动切换身份。

## 实现与接口边界

- 内存会话状态为 unknown、checking、authenticated、guest、error。成功核验的同一身份背景刷新不闪动业务页面；核验失败和外部账号变化清除账号／令牌，既有 revision 机制同步清理身份缓存。游客状态不增加虚假账号版本。
- `/access?redirect=…` 保存本应用路由中的 fullPath。角色和标题从实际匹配路由解析，不信任 query 中的 role。拒绝外部／协议相对地址、反斜杠与控制字符、跨应用 `/mobile` 前缀、API／上传路径、未知路由及认证循环目标。手机由自身 router base 生成 `/mobile/…`，不重复拼接。
- 多标签页变化必须重新核验，不复用旧 generation 的刷新；旧响应不能恢复退出账号或覆盖另一账号。登录／身份切换先等待已发出的旧刷新响应落地，防止失效 Cookie 清理覆盖新凭据。退出和切换失败保留有效会话及错误提示，操作互斥，离开页面后迟到操作不导航。
- 认证 fetch 与全部 `/api/v1/auth/*` 响应使用 no-store；`/auth/refresh` 明确 401 时同步过期当前刷新 Cookie。网络／5xx 不主动清理 Cookie，允许重试。没有新增端点、角色权限、数据库列或默认账号。

## 验证与人工验收

自动回归覆盖无／无效／撤销 Cookie、授权与未授权、手机基址、完整回跳、非法回跳、核验失败恢复、强制改密、退出与刷新竞争、身份变化及操作失败。

以下项目留待人工，不使用浏览器自动化或 Computer Use：

- [ ] 全新无痕窗口访问两端的订单、后台、`/access`：先核验再登录，不露出 user／admin 等账号。
- [ ] 退出后访问原链接、刷新及恢复焦点，不恢复旧账号；多标签页切换／退出后同步正确。
- [ ] 已授权账号从其他身份访问后台：确认切换后回到原筛选、页码及锚点；未授权账号只有有效恢复入口。
- [ ] 更换账号取消／失败／成功，切换失败重试、核验时断网及恢复。
- [ ] PC 品牌顶栏、权限结果区、手机无底部 Tab、窄屏／矮窗口、深浅主题和键盘焦点。
