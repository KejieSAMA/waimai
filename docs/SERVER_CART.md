# 账号服务端购物车（2026-11-13）

游客可以先选购；用户身份登录后，购物车按账号、店铺保存到服务器。一次只结算一家，不合并跨店费用。SQLite 满足当前需求，本轮不引入 Redis、SSE 或库存预占。

## 存储与登录

- 游客使用 `xz-guest-cart`，格式为 `{ version: 1, guestId, snapshot }`。PC 与手机应用使用同一来源和格式；旧 `xz-cart` 仅删除，不迁入服务器。
- 登录后先读取账号购物车，再将游客商品合并。相同商品相加，保留已有账号配送方式、地址选择及备注；新店可采用游客配送方式和备注，不导入游客地址。失效商品跳过，新增数量按库存及限购约束并告知原因，不降低账号原有数量。
- guestId 为随机值，合并与回执同事务；响应丢失后用相同 ID 重试不会重复累加。同一份游客内容不会在另一个账号重复导入。只有确认成功后清除游客副本，失败保留并提供重试。
- 账号购物车只在内存中展示服务器状态，不写 localStorage。刷新从服务端恢复；退出或切换身份立即隔离旧商品、地址选择、报价及迟到响应，不将账号购物车转换为游客购物车。非用户身份不能读写用户购物车。

## 同步与冲突

- 进入页面、获得焦点或切回可见状态时同步，监听卸载时清理；不在后台持续轮询。不提供逐操作跨设备实时推送。
- 单设备快速编辑串行保存，合并后续待保存内容，保存成功不会覆盖请求期间的新编辑。保存失败保留当前内存草稿并阻止下单，使用重试恢复；未确认保存的草稿刷新后不保证保留。
- 每店版本独立。并发修改发生 409 时重新读取该店并提示核对，不用旧整车自动覆盖新内容；其他店的待保存编辑不丢弃。库存、下架及营业限制失败也展示具体原因。
- 清空保留版本记录，避免旧请求把已清空商品重新写回。同步不移动清单布局，提示通过独立浮层显示；结算沿用现有金额更新与按钮稳定样式。
- 商品、店铺安全资料读取时刷新；价格及行小计仍由报价接口计算，购物车不保存费用或地址正文。

## 结算与请求恢复

下单前先确认购物车保存完成，再读取店铺、报价并复核金额。提交带 cartRevision 与随机 requestId，服务端在同一事务内验证快照、扣库存、创建订单并清空该版本。本店之后的修改及其他店不受影响。

requestId 按当前商品、配送、地址、备注及版本生成；同标识重试只返回原订单。创建响应丢失时只查询本人该标识订单，不自动再次创建。创建失败保留购物车，成功后仍进入订单详情进行模拟支付。

## 迁移与恢复

- 当前开发库已经先停本项目、执行 SQLite 一致性备份，再生成客户端并部署迁移，随后重启。备份为 `.cache/cart-migration-20261113-090804/before.db`，该目录已忽略，不提交 Git。
- 新增 Cart、CartMerge，Order 增加可空 requestId 和账号内唯一约束；历史订单保持兼容。原三个保留账号的密码、角色不变，原店铺、24 个商品、分类和优惠字段与备份一致，外键检查通过。验证时存在正常登录及账号管理操作，保留这些在线变更，不恢复或删除新资料。
- 其他环境：停止该项目服务；使用 SQLite backup API 创建一致性副本；执行 `pnpm --filter @waimai/backend db:generate`、`pnpm --filter @waimai/backend db:migrate`；重启并检查健康接口。无需重新初始化账号或基础数据。
- 回滚需同时恢复对应数据库备份和代码版本，并先评估备份之后的业务写入；不要仅删迁移记录。后续全量业务清理需一并考虑 Cart 和 CartMerge，不能只清理浏览器。

## 人工验收

1. 游客 A／B 店选购，登录自动合并；云端已有同商品时累加，原配送／地址／备注保留；失效和限购有提示，重试不重复合并。
2. 同账号 PC／手机刷新、切回页面后同步；不同账号及不同身份不串车，退出没有旧账号购物车。
3. 同时修改同店时显示冲突与服务端结果；不同店可独立修改。断网编辑显示重试且不能提交，恢复后保存最后选择。
4. 当前店下单成功只清理本店，创建失败保留；响应丢失不会重复创建，另一设备新增商品不被迟到响应清空。
5. 1／6／24 项、长名称、空车、店铺休息／商品下架、低库存，PC 与手机、深浅主题、矮窗口、安全区及键盘弹起。
