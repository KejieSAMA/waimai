# 商家自配送到达（2026-11-14）

## 业务与接口

商家 PC／手机为配送中（DELIVERING）的外卖（DELIVERY）订单提供“到达”，单笔和批量均先确认已实际送达，然后直接进入已完成（DONE）。不增加配送完成或待收货状态，用户仍可确认完成；待自提流程不变。

- `POST /api/v1/merchant/orders/:id/arrive`：空对象请求，返回现有安全订单详情。
- `POST /api/v1/merchant/orders/batch-arrive`：严格接受 `{ ids: string[] }`，1–100 个不重复且非空的 ID；禁止客户端指定 storeId 等额外字段。返回 `{ results: [{ id, orderNo, outcome, message? }] }`，outcome 为 completed／already_completed／failed。

店铺和会话上下文来自已鉴权请求。批量在产生写入前核对所有订单归属，包含跨店或不存在 ID 时整批 404；其他状态或逐单处理故障作为结果中的失败项，HTTP 200 表示已返回处理结果，不表示全部成功。

每单独立串行化事务内重新核验会话版本、当前商家身份、首次改密和店铺归属／可写状态（OPEN 或 CLOSED）。仅配送中外卖可转换，已完成外卖按幂等成功，不改历史 doneAt；自提即使已完成也不接受到达。成功转换同事务写 doneAt 与 merchant-arrive 审计，提交后发送 updated 事件；不改金额、支付、库存，不重复通知。旧通用订单动作服务拒绝 arrive，避免绕过专用授权入口。

与用户 complete、refund 竞争时，沿用条件更新及事务重试；只能有一次有效转换。已完成会自然进入现有完成时间、近30日月售及评价流程，无数据库迁移。

## 两端交互

PC 配送中页显示当前页多选框，不可到达行禁用；原行内和详情弹窗增加到达，选中后批量栏显示数量及批量到达。表格新增可选的行选择许可和选择锁定参数，默认不影响其他表格。

手机配送中包含既有待自提分组；仅外卖配送中可选。顶部批量／退出批量，底部固定全选已加载、已选数量及批量到达。一次最多100单，全选仅当前已加载可选数不超过100时启用，超过上限提示分批，不静默截断。新增已完成页签，以 status=DONE 查询，不将 DONE 当作旧 stage 参数。

确认框使用店铺名和所选数量，提示直接变已完成；捕获选单快照，提交期间锁定选择、关闭、重复操作及相关界面操作。PC 翻页、两端切筛选／搜索清空选择，手机加载更多保留已加载选项；刷新剔除不再符合条件的项。冻结后清理选择，仍能浏览、关闭详情及退出批量。

成功后刷新当前筛选、计数与打开的详情，PC 页码失效时回最后有效页；批量显示本次完成／已完成／失败汇总，失败明细在可滚动 modal／sheet，避免占满固定页头。只有仍在当前列表且可到达的失败项保留选择。网络响应丢失先刷新核对，不自动重新提交；确认内容和错误保留，服务端幂等支持人工重试。卸载／身份变化后不应用旧响应。

两端订单页自动建立静默 SSE；提醒只控制声音，开关不创建重复连接，关闭提醒仍接收状态更新。仅 new_order 且已启用提醒发声，updated 不发声。到达刷新经营统计和角标；用户详情沿用现有15秒轮询／恢复焦点刷新。
