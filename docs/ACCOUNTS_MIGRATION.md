# 正式账号迁移与管理员初始化

## 发布顺序

1. 配置独立随机签名密钥，至少 32 字符；开发、生产均拒绝模板值。升级前备份 `.env`、SQLite 数据库和上传目录，备份不提交 Git。SQLite 运行时使用在线 backup API，或停止服务后同时处理 WAL／SHM，再复制数据库，不能在写入时直接复制主文件。
2. 将备份复制到隔离目录，先执行迁移并核对 User、Store、Product、Order、OrderItem、Address、Review、AuditLog 数量和 `PRAGMA foreign_key_check`。失败不升级原库。
3. 在仓库根目录执行 `pnpm --filter @waimai/backend db:generate` 与 `pnpm --filter @waimai/backend db:migrate`。不需要生产编译。旧单角色成为角色授权关联；旧账号 username 继承原登录标识、ID 不变，账号全部禁用、旧密码清空，旧会话删除，关联店铺冻结。既有业务记录保留。
4. 执行 `pnpm --filter @waimai/backend account:init`。必须使用本机交互终端，输入新的、未占用的管理员账号名，隐藏输入两次密码。已有启用管理员时拒绝再次初始化；不会提供默认密码。
5. 登录对应管理端，在账号管理中核对旧账号、重置临时密码、授予角色并启用。临时密码账号首次登录只能改密，改密后重新登录。商家启用后另到商家管理解冻店铺；未启用或没有商家授权时不能解冻或通过审核。

## 账号恢复与会话

- 普通账号忘记密码联系管理员。管理员在本机执行 `pnpm --filter @waimai/backend account:recover` 恢复已有管理员，恢复后必须改密；命令不能将普通账号提升成管理员。
- 旧版分角色 Cookie 不再被接受，新登录清理旧 Cookie。一个浏览器只保存当前账号、当前角色。PC／手机／标签页身份变化通过不含令牌的 storage 信号重新读取服务端会话；Cookie 保持 httpOnly。恢复接口不重写统一 Cookie，避免迟到响应覆盖显式切换后的凭据；旧角色 Cookie 在恢复失败时也清理。
- 改密、停用、重置和授权变更撤销账号全部会话；切换身份提升会话版本，旧角色 access token 失效。SSE 在变更事件与定时复查时断开无效会话。
- 临时密码、正式密码、access token 和 refresh 凭据均不得写入审计、应用日志或部署文档。管理员创建／重置时输入的临时密码只保存在当前表单，操作后清理。

## 本机执行记录

2026-11-12 已使用 SQLite 在线备份生成 `.cache/before-accounts-20261112-155126.db`，在 `.cache/account-migration-verify.db` 执行升级 SQL。升级前后保持 User=14、Store=12、Product=57、Order=6、OrderItem=12、Address=1、Review=0、AuditLog=0，外键校验通过；随后原库通过 Prisma 部署迁移。弱本地签名密钥已替换为随机值，未输出或提交。

首管理员凭据由本机操作者通过初始化命令设定，本轮没有生成固定或演示管理员。

随后按操作者指定恢复现有 `admin` 管理员：保留原 ID 和授权、启用账号、重设密码并撤销旧会话，首次登录仍须改密；指定密码未写入项目文件或日志。恢复前另做在线数据库备份。最新密码下限为 8 个 Unicode 字符、上限 72 字节；其他旧账号及店铺状态不自动恢复。

## 回滚

停止应用和所有数据库连接后，将迁移前数据库备份与匹配的旧代码一并恢复；不要只回滚代码而继续使用新结构数据库。恢复前保留升级后数据库快照，以免丢失升级后发生的业务操作。密钥变更与回滚后仍要求重新登录。

## 人工验收

- PC／手机普通用户注册登录、首次改密、忘记密码提示、退出及重新登录。
- 只有被授权的角色出现在账号设置，普通用户直接访问后台与篡改请求均被拒绝；授权账号显式切换后进入对应角色。
- 管理端账号查询、创建、编辑、授权、启停用、重置、审计；详情失败重试、长列表分页、密码清理、深浅主题、modal／sheet 和键盘。
- 标签页及 PC／手机切换身份后不显示旧账号地址、金额或商家上下文；旧会话、禁用与撤权生效，SSE 断开。
- 不编译、不使用自动 UI 验收。
