# PC 我的订单列表与详情（2026-11-14）

## 本轮实现

仅调整 PC 用户订单，继续使用方案 A 和 ant-design-vue。没有修改手机端、后台订单卡、共享 UI、交易接口或数据库。个人中心侧栏、列表筛选、分页及外层 ScrollArea 沿用现状。

- 列表改为单列横向订单卡，分店铺／商品摘要、状态、金额、操作四区。商品摘要两行省略并提供全文 title，入口为真实订单链接。内容区小于 800px 时金额与按钮移至下方，更窄时继续换行。
- 待支付列表主按钮为“去支付”，只进入详情；已完成未评价主按钮为“评价”。查看和再来一单使用次级按钮；再来一单继续调用既有报价验证、单店替换确认及服务器购物车同步逻辑。
- 详情顶栏仅返回与标题。状态横幅突出真实状态、下一步说明、操作及正常订单进度；退款、取消不显示正常进度，不编造历史节点时间、骑手信息或预计送达。
- 左侧商品卡展示名称／规格、快照单价、数量及服务端行小计，底部右对齐费用及突出合计；右侧为配送及订单资料。小于 880px 改为单列，小于 560px 使用纵向进度和紧凑商品行，避免挤压数字列；不增加商品表内部纵向滚动。
- 待支付标“应付金额”，正常已支付标“实付金额”，已取消标“订单金额”，不表示已退款到账。零配送显示免配送费，无优惠和无备注不占位。
- 订单无图片快照，使用占位图，不查询当前商品图片替代历史图片。联系人手机仅尾号；历史地址损坏时显示缺省值，不让页面崩溃。
- 订单编号完整可读并支持复制。HTTP 或剪贴板拒绝时提供可选中输入框与手动复制提示；迟到复制结果不覆盖另一订单。
- 退款保留原请求与输入，取消／完成继续确认；退款编辑关闭及导航离开有放弃确认，提交期间互斥且不能关闭。评价入口与 `#review` 保留，按钮定位并聚焦原评价区域。

## 状态与计时

PC 专用展示模型统一金额标签、说明、进度及按钮优先级，每单最多一个主按钮。共享交易控制器、权限和金额计算保持不变。

倒计时读取服务端 paymentExpiresAt，仅可见待支付详情每秒更新文字，隐藏、结束及卸载清理；期限缺失或损坏不补造。到期禁用支付并请求原控制器核对一次，失败不触发每秒请求；共享控制器原有 15 秒刷新、到期校验和切单响应隔离继续保留。

## 代码验证

- lint、全仓无产物类型检查及完整回归通过，48 个文件 520 项测试。
- 新增 25 项 PC 模型与时钟测试：各状态金额和操作层级、单个主操作、已评价、退款拒绝／介入、配送／自提进度、费用缺省、损坏地址、手机尾号、服务端期限边界、可见性、换单及计时器清理。
- 原订单控制器的加载失败、迟到响应、支付到期、操作互斥、评价及列表请求回归继续通过。没有编译，没有自动 UI 验收。
