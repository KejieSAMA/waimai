## 确认订单页重构

本轮借鉴 [Uber Eats 的提交前审阅流程](https://help.uber.com/en-GB/ubereats/restaurants/article/how-to-place-an-order-on-uber-eats/?nodeId=509d1b2f-087c-4dac-9e94-6ab248e87491)、[Shopify 单页结算](https://help.shopify.com/en/manual/checkout-settings/customize-checkout-configurations/one-page-checkout)及 [Baymard 的可读摘要研究](https://baymard.com/research-articles/accordion-checkout-usability)。左右分栏及手机固定结算栏为本项目的实现决定，未声称已比对外部产品当前像素布局。

- PC 左侧为配送信息、可编辑商品清单和备注；右侧使用 size-cart-panel 宽度吸顶显示费用与提交。长清单随页面滚动，矮窗口仅压缩摘要明细区；低于 768px 转为单列，不触发设备分流。
- 手机使用单列信息和固定底部金额／提交操作；底栏参与既有页面骨架高度分配，保留真实安全区。
- 地址使用可读摘要及更换／编辑入口，选择和表单分别采用 PC modal、手机 sheet。刷新保留有效选择，再回退默认／首项；保存后选中返回 ID，新增默认开关关闭。自提展示真实门店资料，不依赖地址请求成功。
- 商品显示图片、服务端单价、行小计、数量和移除入口；库存、限购、不可购买与休息状态明确提示，不自动删商品。空车隐藏结算区并保留继续选购入口。
- 两端共用购物车与结算逻辑，浏览器存储和路由留在应用层，继续兼容 xz-cart 数组。备注在本次会话内保留，返回店铺后仍存在，换店或成功下单清空。
- 配送、地址、数量变化立即使原报价进入等待状态，迟到响应不覆盖新状态；等待时保留金额并禁用提交，失败后不使用失效报价。零配送费显示免配送费，无优惠不显示 −¥0。
- 提交前复核商品与金额，变化后要求再次点击提交；复核与创建互斥，失败保留输入，创建请求不自动重试。成功后保存订单 ID 并清空对应购物车，跳转失败可继续查看，不重复创建。离开后的响应不强制导航或清空后来修改的新购物车。
- 沿用提交订单 → 订单详情 → 模拟支付，最终金额和库存仍由后端计算；不新增价格锁定承诺、接口、迁移或无支持的送达时间／预约／支付方式。

人工验收：PC 宽窄窗口、1／6／24 项与长名称、吸顶摘要及矮窗口内滚动；手机底栏、键盘和安全区；地址选择／新增／编辑／取消／失败；配送与自提、数量和空车、返回店铺保留备注；金额变化、库存与下架提示、创建失败及订单详情支付；以上均覆盖深浅主题。

未编译或自动验收 UI，原始设计规范及样式保持只读。

## 第二轮：个人中心导航与补充页面交互

- 根因：账号 SideNav 原先由 Orders 页面单独渲染，切到地址、账号设置或订单详情即卸载。现将其上提到个人中心父路由 AccountLayout，四类页面保留相同导航实例；详情仍选中“我的订单”，其余页面按所属项选中。原有 URL、登录守卫、首页与店铺布局保持兼容。
- 顶栏账号可进入账号设置；个人中心页面不再误选“首页”。侧栏保持原稿 220px 宽度、卡片样式，并在长内容滚动时保持可访问。
- 地址列表保留在个人中心内容区，新增操作放入 PageHeader，新增／编辑使用规范 modal；加入空态、加载与失败重试。保存和删除期间防止重复操作，失败保留表单，手机号列表继续脱敏。
- PC 用户、商家和管理账号页改用 PageHeader、InfoList 和桌面操作按钮，消除手机 ListCell 导航与已有侧栏重复的问题；不增加没有后端支持的资料编辑。
- 用户订单卡片标题提供键盘可操作的详情入口，已完成／已取消订单仍可查看完整详情，原有状态操作保持不变。
- PC 订单详情使用 PageHeader、InfoList、商品表格和后端金额；取消与完成增加确认，退款原因放入 modal。显示加载、失败重试和评价结果，提供明确返回订单列表入口。
- 两端共用订单详情请求状态逻辑：订单 ID 改变时清理旧表单，迟到响应不覆盖新订单，离开页面后停止应用响应，操作期间拒绝重复提交。评价成功使用服务端评价 ID，不因二次刷新失败重新显示评价表单。
- 本轮不扩展独立评价列表或优惠券业务；对应侧栏入口继续明确禁用。原始 tokens、组件 CSS 和 design-system 均未修改。

人工验收：订单 → 地址 → 设置 → 订单详情及浏览器前进／后退；直接刷新地址和详情深链接；深浅主题下侧栏选中；长列表滚动时侧栏；地址新增／编辑／取消／删除与网络失败；已完成订单标题入口；退款、完成确认和评价。未进行自动 UI 验收或生产编译。

## 公共布局与组件

- 手机公共骨架按页面区分底部 Tab、购物车和提交操作，补齐新增、编辑、审核、结算等页面返回入口；移除重复正文标题，主题入口保留在“我的”。
- PageSlot 使用 Vue Teleport 的 defer 模式，把页面内操作送入实际导航／底部目标；表单按钮通过 form 属性关联原表单，保留原生校验。
- 商品图片支持最多 5 张的上传、预览和移除；Logo、证照保留原上传处理与权限，隐藏原生文件控件并提供 token 样式。
- ProductRow 补充月售、原价、分类、预警阈值与驳回文案；MerchantRow 补充负责人、时间、订单量、评分与状态操作。
- 后台恢复侧栏分组、实际待办消息入口和角色文案；其余桌面补充页面使用 PageHeader。
- 开发画廊提供 20 个页面的深／浅色原稿和实际业务页面入口，供人工对照；不将 React 参考运行时引入产品。

## 数据及兼容决定

- 商家卡片的商品行金额由后端根据价格快照计算并返回 lineTotalCents，前端仅格式化展示。
- 新增公开店铺评价分页接口，仅返回评价 ID、评分、内容和商家回复；冻结或不可见商家不能通过此接口访问评价。
- 商品 group=review 同时包含审核中与审核驳回；商家订单 stage=DELIVERING 包含配送中及待自提，查询和分页仍由后端执行。
- 管理商家列表返回受相同类目、城市和关键词过滤的状态数量；公开列表不返回审核状态数量。负责人仅在管理接口返回。
- 新增总览统计来自现有数据库，不增加埋点或模型迁移。有效订单和 GMV 按上海日期内创建、已支付且未取消／退款中的订单计算；退款率按同一创建日期范围计算；新入驻使用店铺创建日期口径。
- 进店人数和转化率尚未采集，接口返回 null，界面显示“—”；骑手联系、预计送达、定位距离、渠道区分和上架时段不填虚构值，也不提供无法保存的配置。
- 草稿沿用已有未上架状态；划线价由后端要求高于售价。平台审核与冻结只读规则保持有效。
