# 设计稿对齐记录

## 正式账号、授权身份与账号管理

- 密码最低长度按最新要求统一为 8 个 Unicode 字符，保留 72 字节上限；两端注册／改密与管理员创建／重置的输入约束、提示和服务端校验一致。本机管理员恢复后仍需首次改密。
- 两端登录统一为账号名／密码，用户注册只授予 USER；移除预填演示账号、短信入口、固定验证码和商家公开注册。管理员可为同账号授予多个身份，身份切换放在账号设置，只展示服务端授权列表；不恢复已删除的后台顶栏入口。
- PC／手机共享会话状态与路由决策，浏览器只保留当前账号、当前身份。会话带版本，鉴权逐次查询账号状态与角色；角色切换、停用、撤权和改密使旧令牌失效。跨标签页通过无凭据 storage 信号恢复会话，清理报价、地址选择与商家上下文，并隔离迟到响应；游客刷新失败不产生路由重检循环。
- 管理端新增账号管理：PC 表格与固定右下分页、详情 modal；手机列表与 sheet。筛选按账号／昵称、角色、状态，支持创建、资料、角色、启停用、临时密码和中文审计动作／操作人。详情失败时禁用保存并提供重试，保存失败保留资料并清除密码，避免默认角色覆盖目标账号。
- 账号启用使用 success、停用使用 neutral 的既有 Tag token；新增共享 AccountForm 只处理字段与事件，业务请求留在共享控制逻辑。没有新增 UI 库或修改原始样式。
- 临时密码首次登录仅允许身份查询、改密与退出，改密后重新登录。禁止停用自己、撤销自己管理员身份及禁用最后管理员；商家停用／撤权事务性冻结店铺，账号恢复后需另行解冻，账号未恢复或没有商家角色时不能解冻及通过审核。
- 旧业务数据保留，迁移禁用旧账号、移除旧密码、清空会话并冻结店铺。首管理员通过本机隐藏密码输入的 CLI 创建，不提供默认凭据。初始化和种子不再创建演示经营数据；迁移、副本验证、首管理员和回滚详见 ACCOUNTS_MIGRATION.md。

人工验收：PC／手机登录注册、首次改密、账号页面与授权切换、后台深链接拒绝、管理列表及弹窗、跨标签页身份同步、停用与 SSE 断开，覆盖错误重试、窄／矮窗口、键盘及深浅主题。未编译或自动验收 UI。

## 桌面弹窗与新增分类样式

- 参考 [Atlassian Modal dialog](https://atlassian.design/components/modal-dialog/usage)的标题／关闭、正文与底部操作区组织方式，以及 [Carbon Modal](https://carbondesignsystem.com/components/modal/usage/)的三段结构；沿用盟信现有 token，不引入外部 UI 库或复制其主题。
- 桌面 modal 使用独立标题栏、右上关闭按钮、正文内边距和带分隔线的底部操作区；取消原来标题、表单紧挨的排版。PC modal 获得桌面控件尺寸，手机 center／sheet 与抽屉保留原有变体。
- 焦点裁切来自控件外侧 outline 与滚动视口边缘重合。共享正文增加内容层，保证控件焦点环在裁剪边界之内；桌面正文只有内部视口滚动，不以关闭裁剪掩盖问题。
- 新增分类使用独立关联表单，补充用途说明、占位示例、40 字限制、取消与提交；打开时聚焦带 autofocus 的输入框。Enter 仅提交分类，失败就地提示并保留输入，提交期间禁用重复操作及关闭。创建成功仍自动选中新增分类。

人工验收：新增分类默认／聚焦／输入／回车／失败／重试，输入框四侧焦点环完整；关闭、取消、Escape、提交锁定、焦点恢复；其他 PC modal、嵌套弹窗、抽屉、手机 sheet、矮窗口与深浅主题。未编译或自动验收 UI。

## 多店购物车与用户购买链路

本轮按用户确认的方案调整两端用户购买链路。以下为源码与测试落实记录，不代表已完成视觉验收；后续早期章节中的单店购物车、会话备注及分类过滤行为以本节为准。

| 区域           | 本轮实现                                                                                                                                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 购物车隔离     | 以 storeId 分组，店铺页读取路由对应的绑定视图；进入 B 不显示 A，加购 B 不清空 A。清空与再来一单只作用于对应店铺。PC 顶栏角标为所有店铺商品总件数。                                                                 |
| 持久化         | 已由 2026-11-13 账号服务端购物车方案替代：游客使用 xz-guest-cart，登录后服务端按账号／店铺保存，自动幂等合并；旧 xz-cart 删除不导入，报价与完整地址不落盘，详见 SERVER_CART.md。                  |
| 结算切换       | 商品卡标题为 Logo／店名／件数／切换图标，PC modal、手机 sheet 列出非空购物车。storeId 查询参数支持直达、刷新、前进后退和登录回跳；无参数优先有效结算选择，再取最近修改的非空店铺。显式无效或空店不静默切到另一店。 |
| 报价及下单     | 各店独立报价版本与错误；切店重建页面控制器并重新核对，不混用金额。同店修改数量保留旧金额并标注更新中。提交锁定、再次核对和导航失败恢复保留；成功只清理该店仍与提交快照一致的商品，其他店不受影响。                 |

## 确认订单页重构

本轮借鉴 [Uber Eats 的提交前审阅流程](https://help.uber.com/en-GB/ubereats/restaurants/article/how-to-place-an-order-on-uber-eats/?nodeId=509d1b2f-087c-4dac-9e94-6ab248e87491)、[Shopify 单页结算](https://help.shopify.com/en/manual/checkout-settings/customize-checkout-configurations/one-page-checkout)及 [Baymard 的可读摘要研究](https://baymard.com/research-articles/accordion-checkout-usability)。左右分栏及手机固定结算栏为本项目的实现决定，未声称已比对外部产品当前像素布局。

- PC 左侧为配送信息、可编辑商品清单和备注；右侧使用 size-cart-panel 宽度吸顶显示费用与提交。长清单随页面滚动，矮窗口仅压缩摘要明细区；低于 768px 转为单列，不触发设备分流。
- 手机使用单列信息和固定底部金额／提交操作；底栏参与既有页面骨架高度分配，保留真实安全区。
- 地址使用可读摘要及更换／编辑入口，选择和表单分别采用 PC modal、手机 sheet。刷新保留有效选择，再回退默认／首项；保存后选中返回 ID，新增默认开关关闭。自提展示真实门店资料，不依赖地址请求成功。
- 商品显示图片、服务端单价、行小计、数量和移除入口；库存、限购、不可购买与休息状态明确提示，不自动删商品。空车隐藏结算区并保留继续选购入口。
- 两端共用购物车与结算逻辑，浏览器存储和路由留在应用层。按最新方案，游客本地、账号服务端存储，旧 xz-cart 删除；每店备注独立保存，返回店铺及换店均保留，仅成功提交的匹配店铺版本清空。
- 配送、地址、数量变化立即使原报价进入等待状态，迟到响应不覆盖新状态；等待时保留金额并禁用提交，失败后不使用失效报价。零配送费显示免配送费，无优惠不显示 −¥0。
- 提交前复核商品与金额，变化后要求再次点击提交；复核与创建互斥，失败保留输入，创建请求不自动重试。成功后保存订单 ID 并清空对应购物车，跳转失败可继续查看，不重复创建。离开后的响应不强制导航或清空后来修改的新购物车。
- 沿用提交订单 → 订单详情 → 模拟支付，最终金额和库存仍由后端计算；不新增价格锁定承诺、接口、迁移或无支持的送达时间／预约／支付方式。
